# v0.4 plan: our own MCP server

Goal: the agent gets the terminal as real tools (`read_terminal`,
`run_command`, …) instead of shell scripts that prompt rules teach it to call.
Done when the agent uses the tools without instructions in `GEMINI.md`.

## How it fits

```
┌──────────────────────── Aiterm window ─────────────────────────┐
│  tabs: the user's shell              │  agent panel: agy        │
│  (Terminal + CommandLog)             │                          │
└───────────────▲──────────────────────┴────────────┬─────────────┘
                │ D-Bus (dbus_api.py, unchanged)    │ MCP over stdio
                │                     ┌─────────────▼─────────────┐
                └─────────────────────│ aiterm-mcp (mcp_server.py)│
                                      └───────────────────────────┘
```

- **Another client of the D-Bus API.** The app does not change. agy starts
  `aiterm-mcp` as a child process; it inherits `AITERM_WINDOW`,
  `AITERM_BUS_NAME` and `AITERM_OBJECT_PATH` from agy (checked with agy 1.3.2),
  so it finds the window exactly as `aiterm-left` / `aiterm-run` do. The
  D-Bus calls move into `client.py`, shared by the MCP server and the
  command-line tools.
- **No SDK.** MCP over stdio is newline-delimited JSON-RPC 2.0 with four
  methods that matter here (`initialize`, `tools/list`, `tools/call`, `ping`).
  A small hand-written server has no dependencies to install next to the
  system Python and shows the protocol plainly; it is about 200 lines.
- **Shipped as an agy plugin.** agy loads plugins from
  `~/.gemini/config/plugins/<name>/`: a `plugin.json`, an `mcp_config.json`
  that starts the server, and `rules/AGENTS.md`, which is on only while the
  plugin is. `install.sh` links the repository's `agy-plugin/` there and
  removes the old block from `GEMINI.md`, so the user's own file holds only
  the user's own rules again. `./uninstall.sh` or disabling the plugin in agy
  turns everything off at once.
- **Guidance lives in the tools.** What the rules said about each tool
  (check the exit code, the user types `sudo` passwords, no pagers, `cd`
  moves the user's folder) goes into the tool descriptions and the server's
  `instructions`, which the client puts in front of the model with the
  tools. `rules/AGENTS.md` keeps only what is not about one tool: run shell
  commands through `run_command`, not the agent's own hidden shell. (Checked:
  with the tools and `instructions` alone, agy answered "which python3?" from
  its own shell; with the plugin's rules it uses `run_command`.)
- **Outside aiterm the plugin is silent.** When agy runs in another terminal,
  `AITERM_WINDOW` is not set and the server lists no tools.

## Tools

| Tool | Arguments | Returns |
|---|---|---|
| `read_terminal` | `commands` (default 1), `whole_screen` | The terminal's folder and the last commands with output and exit codes, or the whole scrollback |
| `run_command` | `command`, `timeout` (default 60 s) | status, folder, command, output, exit code |
| `wait_for_command` | `timeout` | Same, for the command that is already running |
| `get_cwd` | | The folder of the user's terminal |

Every result is text for the model plus `structuredContent` with the same
fields. A refusal (the user is typing, a program is running) is a tool error
(`isError`) that says why and what to do; a timeout is not an error, its text
says to wait or tell the user what to type.

## Steps

1. [x] **MCP server**: `client.py` (D-Bus client, used by the tools too),
   `mcp_server.py`, `bin/aiterm-mcp`. Tests: the protocol on its own, then
   every tool against the real app in the GTK smoke test.
2. [x] **agy plugin**: `agy-plugin/` with `plugin.json`, `mcp_config.json`,
   `rules/AGENTS.md`; the installer links it and drops the `GEMINI.md` block
   and the `aiterm-left` / `aiterm-run` permissions. Checked by hand with
   the real agy in the panel.
3. [x] **Docs**: README (architecture, safety model, install), roadmap ticked.

`aiterm-left` and `aiterm-run` stay as command-line tools for scripts and
debugging; the agent no longer needs them.

## Out of scope for v0.4

- MCP resources and prompts (only tools)
- The HTTP transport: agy starts the server itself, so stdio is enough
