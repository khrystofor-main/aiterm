# v0.3 plan: the agent in the panel

Goal: everything v0.1 does, in one window and without tmux. `agy` runs in the
agent panel; `aiterm-left` and `aiterm-run` talk to the app instead of tmux.
Done when the tmux version can be retired.

## How the agent reaches the terminal

```
┌──────────────────────── Aiterm window ─────────────────────────┐
│  tabs: the user's shell              │  agent panel: agy        │
│  (Terminal + CommandLog)             │  (its own VTE terminal)  │
└───────────────▲──────────────────────┴────────────┬─────────────┘
                │ D-Bus: io.github.khrystofor_main.Aiterm.Terminal
                │                                    │ shell tool calls
                │                      ┌─────────────▼─────────────┐
                └──────────────────────│ aiterm-left / aiterm-run  │
                                       │ (D-Bus clients)           │
                                       └───────────────────────────┘
```

- **D-Bus, not a socket of our own.** The app is already on the session bus
  under its application ID (that is how a second launch opens a window in the
  running process). It exports one more interface on the same connection, so
  there is nothing to start, no port and no file to clean up, and the bus
  only lets the same user in. `gdbus introspect` shows the API, which helps
  debugging.
- **Which terminal.** The agent in a window works on that window's selected
  tab. The app starts `agy` with `AITERM_WINDOW=<window id>` and
  `AITERM_BUS_NAME=<the app's unique bus name>` and `AITERM_OBJECT_PATH`
  (the unique name and the path work for a second, non-unique instance too,
  such as the tests'); the tools pass the window id in every call.
- **The API is the base for v0.4.** The MCP server of v0.4 is another client
  of the same D-Bus interface, so nothing in the app changes for it.

### Interface `io.github.khrystofor_main.Aiterm.Terminal`

| Method | Returns | Notes |
|---|---|---|
| `ReadCommands(window u, count i)` | folder, list of (command, output, exit code, seconds) | From the command log; `count = 0` means all |
| `ReadScreen(window u)` | folder, text | The whole scrollback, for full-screen programs and the `all` mode |
| `RunCommand(window u, command s, timeout u)` | status, folder, command, output, exit code | Types the command, waits for the command log to report it |
| `Wait(window u, timeout u)` | same as `RunCommand` | Waits for the command that is already running |

`status` is `done`, `busy` (a program is running), `typing` (the user has
text on the prompt line) or `timeout` (still running; partial output). The
checks and the `sudo -K` guard of v0.1 move into the app.

## Steps

Each step is one PR. The tmux version keeps working until the last one.

1. [x] **D-Bus API** in the app (`dbus_api.py`): the four methods above, the busy and typing checks, the sudo guard, a 300-line output cap. Tested with a real client over D-Bus.
2. [x] **Tools as D-Bus clients**: `aiterm-left` and `aiterm-run` call the app when `AITERM_WINDOW` is set, with the same arguments, output and exit codes as now (plus the exit code line). With `AITERM_LEFT_PANE` they still use tmux.
3. [ ] **agy in the panel**: the panel runs `agy` in its own terminal with the `AITERM_*` variables. Alt+Enter moves focus between the shell and the agent (and opens the panel when it is closed). If `agy` is missing, the panel says how to install it; when it exits, a button restarts it.
4. [ ] **Rules**: `rules/aiterm.md` describes the new layout ("your terminal on the left" stays true), the exit code in the output, and drops the tmux-specific parts.
5. [ ] **Retire tmux**: `aiterm` starts the GTK app, the installer stops needing tmux and drops the "AI Terminal" launcher, `config/tmux.conf` and the tmux tests go, and the README describes one app.

## Out of scope for v0.3

- The MCP server (v0.4)
- A native chat UI instead of agy's TUI (v0.5)
- Several agents per window
