# v1.0 plan: the release

Goal: aiterm installs like any Ubuntu app, its tests run on every change,
and the README shows what it does.

## Steps

1. [x] **CI** (`.github/workflows/tests.yml`): `tests/run.sh` on every pull
   request and push to main, in an `ubuntu:26.04` container (the app needs
   VTE 0.80+ and libadwaita 1.8), GTK under Xvfb with the cairo renderer and
   its own session bus. CI's slow software renderer found three real bugs:
   command marks starved by redraws, the approval bar resizing the terminal
   while a command was typed, and a typed-ahead command cut short in the log.
2. [x] **`.deb` package** (`packaging/build-deb.sh`): the files git tracks
   under `/usr/lib/aiterm`, the commands in `/usr/bin`, `Architecture: all`,
   dependencies from the archive. A package cannot change the user's
   `~/.gemini`, so the agent panel offers that step (`aiterm-agent-setup`).
   CI builds the package on every push. A `.deb` rather than a Flatpak: the
   agent must run commands in the user's real shell and system, which a
   Flatpak sandbox would have to break out of anyway.
3. [x] **Demo GIF** (`packaging/demo.py`): window snapshots of the real app
   with the real agy, put together with Pillow; no screen recorder.
4. [x] **Version 1.0.0** and a draft GitHub release with the package attached.
   Publishing it (which creates the `v1.0.0` tag) is the owner's step.

## After 1.0

- Make Aiterm the default terminal, opt-in (`install.sh --default-terminal`)
- Compare models in the evals (`evals/run.py --model …`)
- Show the agent's file edits as diffs in the chat
